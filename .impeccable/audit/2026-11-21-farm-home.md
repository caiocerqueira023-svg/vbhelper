# Tamers Lab — farm Home screen audit

Native Android audit (Impeccable `audit` + `audit.native`, Compose/Filament surface). This is a
**technical** quality audit: it documents and scores what the current source and the supplied
runtime capture prove, and does not fix anything.

- **Snapshot:** 2026-11-21, worktree at `89dbe649` (VBHLLMVer.58) plus uncommitted UI changes.
- **Scope:** the farm Home surface — top status HUD, partner slab + 3-detent partner overview,
  5-place row, roster / menu / resident sheets, boot cover, and the persistent 3D Digifarm behind
  them (`app/src/main/java/com/tamerslab/farm/ui/home/*`, `app/src/main/java/com/tamerslab/home/ui/*`,
  `farm/ui/digifarm/*`, `navigation/AppNavigation.kt`, `ui/theme/*`).
- **Authority:** current source; `PRODUCT.md`; `DESIGN.md` (tokens, Farm home shell, Do/Don'ts);
  `.impeccable/surfaces/farm-home.md`.
- **No fixes were applied.** Detail reports for each dimension are retained in `build/audit-home/`
  (`a11y.md`, `perf.md`, `platform.md`, `theming.md`).

## Evidence and limits

- **Source-level audit, not an on-device verdict.** No device is attached (`adb` is not installed on
  this machine) and no Gradle build was run (the wrapper cache is outside the workspace sandbox).
  TalkBack speech, frame times, allocation counts and hit rectangles are therefore inferred from
  code unless noted.
- **Rendered evidence:** the supplied capture, 738×1600 px preview of a 1080×2340 px Samsung frame —
  **360×780 dp at density 3.0 with 3-button navigation**, Digimon.net (light) palette. Its geometry
  matches the source: the place band measures 70 dp, the peek slab 96 dp, the status bar 27 dp and the
  3-button strip 48 dp; the repo's own accessibility dump (`.plan/ui_home.xml`, 1080×2340) records the
  96 dp slab node at exactly 288 px.
- **Capture freshness caveat:** the chrome composites agree with the current Digimon.net tokens
  (slab ground rendered `#E4E7FA`, modelled `#E4E7F9`; HUD ground ≈`#E5E5EF`), but the scene backdrop
  reads warm grey `#E3E0DB` while HEAD paints the farm skybox flat `backgroundAlt` `#F4F7FF`
  (`Digifarm3dViewport.kt:191,676-678`). Either the Filament tone map shifts the pale sky or the
  capture predates HEAD; scene-dependent contrast findings below stay flagged for recapture.
- **Contrast method:** sRGB relative luminance, WCAG 2.x (normal text 4.5:1, large 3:1, non-text 3:1).
  Opaque pairs use the exact palette hex; translucent chrome is composited source-over against
  measured scene grounds (pale sky `#E3E0DB`, island underside ≈`#101018`, bright cube ≈`#EFF2FF`).
- **Markers:** P0 blocking · P1 major (fix before release) · P2 minor · P3 polish. Repeated instances
  of one systemic problem share a finding.

## Platform conformance verdict

**PASS for native architecture; FAIL on several platform contracts.** This is not a ported website:
it is a real Compose Android app with a deliberate edge-to-edge shell, `ModalBottomSheet`s, a hoisted
`BackHandler` ladder (Expanded → Half → Peek → system), lifecycle-gated Filament rendering, system
reduced-motion handling and palette-resolved system-bar *icon* appearance. The custom game chrome is
appropriate to the product rather than a Material lookalike.

The exceptions are concrete and should be fixed before the surface is called native-complete:

1. `systemGestureExclusion()` is attached to a full-route node instead of the 96 dp drag handle
   (`FarmHomeScreen.kt:186-193`, `PartnerDeck.kt:187-190`), so the registered exclusion is essentially
   the whole window rather than the deliberate slab area.
2. Predictive Back is not opted in (`AndroidManifest.xml` has no `enableOnBackInvokedCallback`; no
   `PredictiveBackHandler` exists) on a `targetSdk 37` app, so the signature sheet ladder cannot track
   the gesture.
3. System bars are painted opaque from the palette in three places (`themes.xml`, `Theme.kt:34-47`,
   `MainActivity.kt:88-92`), which cancels the full-bleed world the shell is built around on API ≤34
   and renders differently on API 35+ where those colour writes are ignored.

## Executive summary

- **Audit health score: 10/20 — Acceptable.** Scores are rubric judgments from verified source and
  one supplied capture; no on-device score is claimed.
- **Top findings**
  1. **TalkBack loses the two always-visible readings.** The partner slab's `contentDescription` is
     "Partner overview" and the farm chip's is "Who is in the Digifarm", set on merging clickable
     nodes, so the name/stage/vitals/mood and the "8/12" count are masked (H01). The 3D world exposes
     nothing at all (H02).
  2. **Light palettes break on the new home.** The 0.82-alpha slab over the island's dark underside
     drops the stage line to 4.07:1 and the HP reading to 3.60:1 (H03), and opaque white system bars
     frame the world top and bottom, hiding the place-row ground that was deliberately painted under
     the nav bar (H04).
  3. **The farm never idles.** Ambient walking/sleeping counts as "animating", so the 60 fps tier runs
     for the whole session and the authored 30 fps idle tier is effectively dead (H05).
  4. **A system-gesture trap risk.** The whole route asks the OS to release edge gestures (H06); on
     gesture navigation this can deaden edge-Back in the lower screen. Verified in code, needs a
     device to confirm the trap.
  5. **Fixed chrome vs. font scale.** At 2.0× the 96 dp slab cannot hold the vitals and the 70 dp place
     band overflows while captions auto-shrink toward 8 sp (H07).
- **Recommended next steps:** correct the bar/inset ownership (H04, H16), bound the gesture exclusion
  (H06), make the slab and world accessible (H01, H02), fix light-palette contrast (H03), restore the
  30 fps idle budget (H05), then work down the P2 list and finish with `/impeccable polish`.

## Detailed findings — P1 major

### H01 — The partner slab and the resident count announce static labels instead of their values

- **Location:** `home/ui/PartnerDeck.kt:597-611` (`onClickLabel` + `contentDescription` = `paneTitle`),
  `:618-676` (name / `Stage · Attribute` / vitals texts, chat and chevron `IconButton`s),
  `:638-643` (mood dot); `farm/ui/home/FarmHomeHud.kt:174-185` (`contentDescription` = chip label),
  `:205-240` (count Text + 12-slot gauge `Canvas`); `res/values/strings.xml:93`
  ("Partner overview"), `res/values/strings_farm_home.xml:16-17` ("Who is in the Digifarm", "%1$d/%2$d").
- **Category:** Accessibility — names, roles, state.
- **Evidence:** both nodes are merging clickable containers with a static `contentDescription`; the
  actual values are separate text children and the gauge is a bare `Canvas` with no semantics. The
  repo's earlier accessibility dump (`.plan/ui_home.xml`) shows the same shape: a `content-desc` node
  plus bare value `TextView`s beneath it. TalkBack gives a node's `contentDescription` precedence in
  the normal utterance path, so the slab is likely read as the destination name and the count as the
  function label; the mood is colour-only on top of that.
- **Impact:** the one card that answers "who is with me and how are they", and the roster reading the
  HUD exists for, are not reliably available to screen-reader users. WCAG 4.1.2 / 1.3.1. This is the
  first screen of the app.
- **Guideline:** Material 3 semantics; WCAG 4.1.2 (name/role/value), 1.3.1 (info & relationships).
- **Recommendation:** remove the static descriptions and build the node deliberately: slab label =
  partner name + stage · attribute + vitals + mood summary, `onClickLabel = "Expand partner
  overview"`; chip label = "Who is in the Digifarm, 8 of 12" (or let the merged "8/12" read with a
  distinct action label), and give the gauge `progressBarRangeInfo` or a text alternative.
- **Suggested command:** `/impeccable clarify`

### H02 — The Digifarm scene and every resident action are unreachable for TalkBack

- **Location:** `farm/ui/digifarm/Digifarm3dViewport.kt:174-281` (`AndroidView` hosting a
  `TextureView`; no semantics, `contentDescription`, `importantForAccessibility` or click listener in
  the file), `:1422-1465` (sprite hit-testing; the projections needed for virtual nodes already
  exist); `farm/ui/digifarm/FarmHomeWorld.kt:325-339`; `farm/ui/home/FarmHomeScreen.kt:236-272`
  (`FarmResidentSheet` opens only from `shell.selectedResidentId`); `navigation/AppNavigation.kt:151-153`.
- **Category:** Accessibility — missing interactive nodes.
- **Evidence:** residents are tappable only by hit-testing the `TextureView`; the resident sheet
  (follow camera, set active, switch from Storage, remove, chat) has no other entry point, and the
  double-tap recenter gesture is pointer-only.
- **Impact:** a whole task class (inspect/follow/manage a resident from the island) is impossible for
  TalkBack and switch-access users. WCAG 1.1.1, 2.1.1, 4.1.2.
- **Guideline:** every meaningful operation needs an accessible equivalent; pixels in an `AndroidView`
  do not create virtual nodes automatically.
- **Recommendation:** expose the residents as accessibility virtual nodes over their projected
  rectangles (the view already computes them), with named actions; or, at minimum, add a "Residents on
  the island" row to the roster sheet that opens `FarmResidentSheet`, plus a labelled "Recenter
  camera" action.
- **Suggested command:** `/impeccable harden`

### H03 — Translucent chrome over the live scene fails AA in the light palettes

- **Location:** `home/ui/PartnerDeck.kt:409` (slab ground = `SurfaceElevatedPurple` @
  `PartnerSlabAlpha`), `PartnerDeckContract.kt:24` (0.82), `PartnerDeck.kt:629-648` (stage line,
  vitals), `:967-1003` (accent HP number, muted "/ 9,999", track); `farm/ui/home/HudChrome.kt:29-58`
  (top 0.82 → 0.451 → 0; bottom 0.82 → 0.90 → 0.96), `:61-69` (black text shadow);
  `FarmHomeHud.kt:250-270` (gauge empties = `textPrimary` α0.22), `:355-365` (hairline α0.12);
  `ui/theme/AppTheme.kt:172-185` (Digimon.net), `:142-165` (Arena).
- **Category:** Appearance & Theming / Accessibility — contrast, scene-dependent surfaces.
- **Evidence (rendered + token model):**

  | Pair (Digimon.net unless noted) | Ratio | Verdict |
  |---|---|---|
  | slab stage `textSecondary` on slab over island underside | **4.07** (model 4.13) | fail 4.5 |
  | slab HP `accent` on the same ground | **3.60** (model 3.73) | fail 4.5 |
  | slab "/ 9,999" `textMuted` (model, palest slab) | **3.01–4.43** | fail everywhere |
  | Arena equivalents | 4.52 borderline / **3.71** / **3.42** | fail |
  | HUD accent (bits, home glyph) over scrim α0.82 on near-black | 3.81 | fail 4.5 |
  | HUD accent in the α0.60 fade band behind the cluster | **2.19** | fail |
  | 12-slot gauge empty slots vs ground | 1.54–1.96 | fail non-text 3:1 |
  | vitals track vs slab | **1.03–1.41** | fail non-text 3:1 |
  | HUD hairline vs ground | 1.25 | invisible |

  The peek slab sits over the island's dark underside in the supplied capture (ground `#BBC0D4`); the
  camera cuts every 14–26 s (`DESIGN.md:419`), so the ground behind the text is not stable.
- **Impact:** light-palette users get washed-out stage/HP readings and an invisible progress track on
  the surface the product treats as the partner's home; the HUD's own text is only safe while the
  backdrop stays pale. Violates `DESIGN.md:374-376` ("each cluster holds up against sky, ground or
  chasm") and the Vital Signal Rule when accent becomes unreadable. WCAG 1.4.3, 1.4.11.
- **Guideline:** contrast must hold in every state the UI can render; pair semantic surfaces with
  contrast-checked foreground roles; keep non-text state graphics at 3:1.
- **Recommendation:** make the slab ground effectively opaque where text sits (raise
  `PartnerSlabAlpha` to ≥0.94 for light palettes after a visual check, or add an ink plate behind the
  text column); move "/ 9,999" to `textSecondary`; hold the top scrim at a ≥0.7 plateau through the
  cluster band; raise gauge-empty ink to ≈0.55 and give the vitals track a role that clears 3:1 on the
  slab; add a contrast unit test over all four palettes and worst-case grounds.
- **Suggested command:** `/impeccable colorize`

### H04 — Opaque system bars cut the full-bleed farm off at both window edges

- **Location:** `app/src/main/res/values/themes.xml:5-9,17-29` (opaque `statusBarColor`/
  `navigationBarColor` per palette); `ui/theme/Theme.kt:34-47` (bar colour = `palette.background`,
  re-applies `enableEdgeToEdge`, then sets `window.statusBarColor`/`navigationBarColor`);
  `MainActivity.kt:88-92`; Home consumes zero system insets (`navigation/AppNavigation.kt:251-256`)
  and `PlaceDock.kt:74-88` deliberately paints the row ground under the nav-bar inset.
- **Category:** Platform Conformance / Appearance & Theming — edge-to-edge.
- **Evidence:** in the supplied capture the status band and the 3-button nav band are pure `#FFFFFF`
  with hard steps at y≈55 px and y≈1501 px (738-wide), while the HUD ground below the bar is
  ≈`#E5E5EF` and the row ground ≈`#E4E7FA`. The world never reaches the window edge; the 48 dp nav
  band hides exactly the ground the row paints under it; the top scrim's y=0 edge is covered, leaving
  a 1.28:1 white seam that reads as a shelf — the composition the surface brief refuses.
- **Impact:** the Farm home shell contract ("the 3D habitat fills the window edge-to-edge",
  `DESIGN.md:366-369`) is not delivered in the light palettes; the place row no longer "owns the very
  bottom" (`DESIGN.md:378-385`) on 3-button navigation. On API 35+ (targetSdk 37) the colour writes
  are ignored, so the same build renders differently across OS versions.
- **Guideline:** Android edge-to-edge with transparent system bars; per-screen scrims carry contrast
  (`reference/android.md:15`); `DESIGN.md:359-360` requires the shell to consume system and cut-out
  insets.
- **Recommendation:** on the Home route pass transparent `SystemBarStyle` scrims (or draw a
  palette-aware bar scrim inside the HUD/row ground), delete the direct `window.*BarColor` writes and
  the per-theme bar colours, and keep only the (already correct) light/dark icon appearance. Verify on
  API 34 and API 35+, with gesture and 3-button navigation.
- **Suggested command:** `/impeccable adapt`

### H05 — The farm always renders at 60 fps; the authored 30 fps idle tier is unreachable

- **Location:** `farm/ui/digifarm/Digifarm3dViewport.kt:533-543` (`isAnimating()`), called from
  `:464` every frame; tier rule `rendering/FrameBudget.kt:42-49`.
- **Category:** Performance — frame loop / power.
- **Evidence:** `isAnimating()` returns true when any resident `segmentActive` (walking), any held
  gesture (sleep breath lasts 30–60 s, hop 1.5 s), streaming, or the followed resident is catching up.
  With up to 12 residents and 42 % walk odds per beat (`DESIGN.md:509-516`), the all-still condition
  for `Idle` is essentially never true; the only recorded farm window (≈64 fps median,
  `docs/performance/BASELINE.md` §3 row 3) is consistent with the 60 fps tier running while untouched.
- **Impact:** twice the render/transform/GC work on the app's most-visited screen, for battery and
  thermal budget the design explicitly says it does not need (`DESIGN.md:475-477`).
- **Guideline:** render only what changes, at the rate it needs; honour the documented frame budget.
- **Recommendation:** separate ambient life from interaction: keep `Active` for touch/camera/asset
  streaming, run walking/sleeping/bobbing at `Idle` (30 fps), and give a short gesture (hop) its own
  time-capped 60 fps window. Add a benchmark assertion that a no-touch idle window spends most frames
  in `Idle` (`FrameBudgetTest` already pins the policy).
- **Suggested command:** `/impeccable optimize`

### H06 — System gesture exclusion covers the whole Home route, not the 96 dp drag handle

- **Location:** `farm/ui/home/FarmHomeScreen.kt:186-193`
  (`.align(BottomCenter).navigationBarsPadding().systemGestureExclusion()`), applied to
  `PartnerDeck`, whose root is `BoxWithConstraints(modifier = modifier.fillMaxSize())`
  (`home/ui/PartnerDeck.kt:187-190`);
  contract `DESIGN.md:411-413` ("the slab claims its drag area above the navigation-bar strip").
- **Category:** Platform Conformance — system gestures.
- **Evidence:** the modifier chain resolves to a node that fills the route (window height minus the
  nav-bar inset), so the exclusion rectangle registered with the OS is the whole Home surface rather
  than the slab. Android's own contract limits exclusions to small precision regions and caps the
  honoured vertical extent (≈200 dp per edge); the current rect exceeds it.
- **Impact:** the OS clamps an unintended region, so real behaviour depends on undocumented clamping.
  On gesture navigation this can deaden an edge-Back swipe that starts in the lower screen — at Peek
  the user cannot leave Home, at Half/Expanded the documented collapse ladder may not receive the
  gesture. It is also the "swallow system gestures across a large strip" pattern gesture-navigation
  quality guidance flags. Code-verified; the actual trap needs a gesture-nav device.
- **Guideline:** Android `setSystemGestureExclusionRects` — small, precise areas only; Android
  reference "System Back always works; never trap the user".
- **Recommendation:** move `systemGestureExclusion()` inside `PartnerDeck` onto a bounded node: the
  96 dp peek slab / drag-handle bounds only, and remove it at Half/Expanded where nothing needs to
  beat a system gesture. Never attach it to a `fillMaxSize` container. Re-test gesture Back on
  hardware.
- **Suggested command:** `/impeccable harden`

## Detailed findings — P2 minor

### H07 — Fixed chrome cannot grow with the system font scale (WCAG 1.4.4)

- **Location:** `home/ui/PartnerDeckContract.kt:18` (`PartnerPeekHeight = 96.dp`);
  `home/ui/PartnerDeck.kt:192-215,384-391` (sheet laid out to exactly the detent height), `:618-649`
  (slab insides); `farm/ui/home/PlaceDock.kt:51-53` (70 dp band / 62 dp row), `:133-175`, `:156-168`
  (`TextAutoSize` floor **8.sp**); typography `ui/theme/Type.kt:43-49,72-79`; `FarmHomeHud.kt:175-235`.
- **Category:** Accessibility / Adaptivity — text scaling.
- **Evidence:** at 2.0× the slab body box is 96−20 = 76 dp while name (titleSmall 13 sp) + stage
  (labelSmall 11 sp) + vitals need ≈110 dp, so the vitals value/gauge is clipped out of the
  always-visible slab. The place band leaves 69 dp while its content needs ≈72 dp, so the active
  underline overflows; the caption floor of 8 sp means labels shrink back toward the 11 sp role
  minimum instead of scaling. On the design's 360 dp target the HUD readouts (≈214 dp) plus the fixed
  156 dp key cluster exceed the 340 dp content width, squeezing the last key.
- **Impact:** users who scale text lose the vitals and the mood from the first screen and get
  undersized navigation labels — exactly the content the slab exists to carry.
- **Guideline:** WCAG 1.4.4 (resize text 200 %); Material 3 type scaling; `reference/android.md`.
- **Recommendation:** let the peek slab size to content (min 96 dp) with a font-scaled cap; let the
  place band grow or allow two-line captions; raise the caption auto-size floor to ~11 sp; compact the
  HUD keys earlier (or drop the count role sooner) and verify 1.3×/2.0× on a 360 dp phone.
- **Suggested command:** `/impeccable adapt`

### H08 — Muted ink fails AA on elevated surfaces in both dark palettes

- **Location:** `ui/theme/AppTheme.kt:63-65` (Helper `textMuted` `#8A82AC`), `:132-133` (Lab
  `#989898`); usage in the partner deck `/ 9,999` (`home/ui/PartnerDeck.kt:980-985`) and the shared
  overview tile captions (`components/VitalsPanel.kt`, `components/CharacterEntry.kt`, mission slots).
- **Category:** Accessibility — contrast.
- **Evidence:** `textMuted` on `surfaceElevated` = **4.41:1** Helper / **4.06:1** Lab (normal text
  needs 4.5); on `surfaceContainerHighest` (`surfaceHighlight`) = **3.88 / 3.17 / 4.23** across Helper
  / Lab / Digimon.net; the 0.8-alpha instruction line drops to **3.03 / 2.58 / 3.01**. Arena 5.07 and
  Digimon.net 4.52 pass on `surfaceElevated` only.
- **Impact:** mood/trophy/win-rate captions, weekly-chart labels, the vitals suffix and mission
  instructions are hard to read in the two dark identities — including the home overview.
- **Guideline:** WCAG 1.4.3 (4.5:1 normal text); Material 3 contrast roles.
- **Recommendation:** raise dark-palette `textMuted` until it clears 4.5 on `surfaceElevated`/
  `surfaceHighlight` (e.g. ≈`#A49CC4` Helper, ≈`#B4B4B4` Lab) or use `textSecondary` for these labels;
  never dim instruction copy with alpha.
- **Suggested command:** `/impeccable colorize`

### H09 — Live readings change silently (no live regions)

- **Location:** no `liveRegion`/`announceForAccessibility` usage in `farm/ui/home` or `home/ui` (grep);
  bits `FarmHomeHud.kt:274-295`; resident count `FarmHomeScreen.kt:72-118`; slab vitals
  `PartnerDeck.kt:967-1003`; mission rows that change in place `home/ui/screens/VBDiMHomeScreen.kt:180-198`.
- **Category:** Accessibility — status messages.
- **Evidence:** bits after a reward/purchase, the resident count after a roster edit, vitals/mood
  updates and mission progress all update visually with no announcement. The app already uses polite
  live regions elsewhere (`components/ChatConversationUi.kt:217`).
- **Impact:** a TalkBack user must leave and re-read a node to notice that the value changed — for
  currency and vitals that is the only feedback the screen gives. WCAG 4.1.3.
- **Recommendation:** `Modifier.semantics { liveRegion = LiveRegionMode.Polite }` on the bits reading,
  the resident-count cluster and the slab vitals group; announce mission state changes.
- **Suggested command:** `/impeccable harden`

### H10 — Sheet detent changes are silent, focus is not managed, and Expanded is not modal to a11y

- **Location:** `home/ui/PartnerDeck.kt:208-247` (height state / body swap), `:284-297` (full-screen
  scrim = plain `Box(...).clickable {}`, no label/role/dialog semantics), `:411` (`paneTitle` set from
  Peek onward), `:650-674` (only the chevron label changes); `FarmHomeScreen.kt:108-146` (HUD becomes
  `invisibleToUser` only after the fade), `:157-173` (dock hidden past the 0.5 progress threshold);
  `farm/ui/digifarm/FarmHomeWorld.kt` (world layer always composed).
- **Category:** Accessibility / Platform Conformance — state announcements, focus, modality.
- **Evidence:** opening/half/expanded changes the whole screen but announces nothing; no
  `stateDescription` says Peek/Half/Expanded; no focus requester moves focus into the sheet or back to
  the chevron; when Expanded hides the HUD/dock, a focused node there is dropped; the unlabeled scrim
  is focusable as an anonymous button.
- **Impact:** TalkBack users cannot tell the sheet opened or where they are, and traversal can still
  reach chrome behind an apparently modal surface. WCAG 3.2.1 / 4.1.2; Material 3 state announcement
  and modal focus expectations.
- **Recommendation:** add `stateDescription` to the slab/sheet; request focus on open and return it to
  the chevron on collapse; label the scrim "Collapse partner overview"; mark the chrome behind the
  sheet `invisibleToUser` from the start of Expanded (not only after the fade).
- **Suggested command:** `/impeccable polish`

### H11 — The favourite swipe mutates global partner state with no announcement or accessible equivalent

- **Location:** `home/ui/PartnerDeck.kt:249-282` (`deckGesture`), `:280` (horizontal swipe →
  `state.cycleFavorite`), `:1095-1151` (axis lock, 40 dp threshold);
  `home/ui/PartnerOverviewState.kt:147-160` (`cycleFavorite` → `setActive(..., announce = false)`).
- **Category:** Accessibility — pointer-only interaction.
- **Evidence:** a horizontal swipe on the slab silently changes the app-wide active partner, with

- **Impact:** TalkBack/switch users cannot perform the operation, and sighted users can trigger an

- **Recommendation:** expose "Next partner"/"Previous partner" custom actions on the slab (and keep
  the existing portrait-card actions), and announce the change instead of suppressing it.
- **Suggested command:** `/impeccable harden`

### H12 — Mood is only an unlabeled 8 dp colour dot; the qualitative summary never reaches the first viewport

- **Location:** `home/ui/PartnerDeck.kt:629-644` (8 dp `moodDotColor`), `:1005-1011` (thresholds);
  `moodSummary()` exists at `components/ConditionSummaryPanel.kt:37-42` and is shown only in the
  expanded/half overview (`home/ui/PartnerModules.kt:95-125`). Contract: `PRODUCT.md` ("Home shows a
  short qualitative mood summary without a numeric score, keeping its card compact"), `DESIGN.md:730`,
  Do/Don't "Don't depend on colour alone".
- **Category:** Appearance & Theming / Accessibility — use of colour, product contract.
- **Evidence:** on the first screen mood is a colour-only state carried by an 8 dp dot (olive `#675400`
  in the supplied Digimon.net capture), inside a slab whose semantics are overridden (H01); the
  qualitative summary is two gestures away.
- **Impact:** colour-vision users cannot read the state, TalkBack users get nothing, and the documented
  "short qualitative mood summary" is absent from the home card the contract describes.
- **Recommendation:** put the compact summary (`moodSummary(mood)`) in the slab (e.g. its own label
  chip next to stage/attribute, or a short text after the dot) and include it in the slab's

### H17 — Frame hot path: per-frame thermal binder traffic and ~1,100 scratch arrays per frame

- **Location:** `farm/ui/digifarm/Digifarm3dViewport.kt:516-530`
  (`currentFrameTier` → `powerManager?.currentThermalStatus`), called from `:464` every rendered frame
  and `:660-664` on every touch event; mapping `rendering/FrameBudget.kt:51-56`;
  cube solver `Digifarm3dViewport.kt:910-939` and `rendering/CubeCollision.kt:29-48`.
- **Category:** Performance — main-thread jank, allocations.
- **Evidence:** `getCurrentThermalStatus()` is a synchronous service call on API 29+, invoked inside
  `doFrame` (critical path) and per `MotionEvent` during camera work, although thermal status changes
  only on multi-second scales. The collision solver allocates 3 `FloatArray(3)` per cube pair per
  iteration: 14 cubes → 91 pairs × 4 iterations × 3 = **1,092 float arrays per frame**, plus the
  volume/displacement lists — ~1 MB/s of scratch churn at 60 fps on the thread that must submit the
  frame.
- **Impact:** avoidable binder latency and GC pressure inside the 16.7 ms interaction budget; the
  effects are not measured yet (see H05 and the measurement list).
- **Recommendation:** register a thermal-status listener (or sample every ~5 s) and read a field in
  `currentFrameTier`; stop recomputing the tier per touch event; hoist the solver's centres,
  displacements and scratch vectors into the view as preallocated arrays and fill caller-owned buffers
  (behaviour unchanged; `FloatingCubeLayoutTest` already pins the result).
- **Suggested command:** `/impeccable optimize`

- **Recommendation:** keep `alpha` reads inside `Modifier.graphicsLayer { }`, drive visibility switches

## Patterns & systemic issues

1. **Static labels over live data.** Two of the three always-visible readings replace their value with
   a route/function name (`Partner overview`, `Who is in the Digifarm`). This is one implementation
   shortcut repeated on the surface, not two accidents.
2. **Chrome that assumes a dark world.** Translucent grounds, a black text shadow, a
   palette-`base` scrim and 0.12–0.22 alpha hairlines/gauge empties were tuned against the dark
   palettes; the light palettes inherit the geometry but not the contrast (`H03`, `H20`, `H21`).
3. **The interaction surface is not the accessibility surface.** Residents, the favourite swipe and
   the recenter gesture exist only as pointer gestures on live 3D/canvas chrome (`H02`, `H11`, `H22`).
4. **Fixed dp chrome vs. scalable type.** The slab, place band and HUD are laid out in fixed dp while
   every label scales with the user font setting (`H07`).
5. **Local copies of shared systems.** Home re-implements the shared HUD chrome and the shared
   `HudKey`, and the copy is where the only raw colour on the surface lives (`H20`); the small
   `TextAutoSize` floor and the opaque-bar writes are the same "local shortcut over shared contract"
   pattern (`H23`, `H04`).
6. **Android adaptation was deferred.** No window size class, no landscape composition, no cut-out
   insets, and configuration changes rebuild the world the shell was designed to keep (`H15`, `H16`).
